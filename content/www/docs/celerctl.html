celerctl — a chave de fenda

Ferramenta USB do CelerOS, estilo adb: fala com o aparelho pela serial (ou pelo bridge WiFi) e faz de tudo — shell, arquivos, screenshot do framebuffer, injeção de toques, install de apps, logs, debugger JS e até gravar firmware sem esptool. É um script Python único no repo do firmware: tools/celerctl.py.

pip install pyserial Pillow p/ screencap USB · WiFi bridge

Conectar #

▸bash
CTL="python3 tools/celerctl.py"     # no repo CelerOS

$CTL devices                        # lista USB + bridges WiFi vistos
$CTL -p /dev/ttyUSB1 info           # versão, board, api, heap, discos
$CTL -p 192.168.0.220:5555 info     # mesma coisa, pela rede (após pair)

O -p aceita porta serial, prefixo do serial USB da placa ou IP do bridge. O protocolo negocia sozinho (proto 2 = CRC32 + janela; --proto 1 força o caminho legado).

Comandos #

ComandoO que faz
deviceslista placas conectadas (USB e WiFi) com versão/board/api
pair · provisionpareia o bridge WiFi (1×) · salva WiFi + token + permissões de app
info · top · statsestado do sistema · CPU% por task em tempo real · foto de profiling
shellshell interativo ou shell "comando" (ls, cat, df, ps, run, reboot…)
ls · cat · push · pull · rm · mkdir · mvsistema de arquivos completo (com -b 921600 voa)
apps list/install/pull/rmgerencia apps instalados — install aceita --sd, --run, --pula-lint
screencap · tap · swipecaptura a tela em PNG · injeta toque/arrasto — automação de UI
logcat · coredumplogs do dispositivo em tempo real · baixa o ELF do último crash
ota pushgrava firmware pela conexão — sem esptool, sem botão
dev · debugloop watch+reload+logs · debugger Duktape (breakpoints, step, eval)

Screenshots e automação #

O screencap baixa o framebuffer real (RGB565) e converte para PNG — todos os screenshots desta wiki vieram daí. Com tap/swipe você navega a UI remotamente:

▸bash — reproduzindo a captura do Snake
$CTL -p /dev/ttyUSB1 screencap tela.png      # tela.png: 320x240

# abre o app (pelo nome do ícone ou pelo shell)…
$CTL -p /dev/ttyUSB1 shell "run Snake"

# …joga: swipe circular cima→esq→baixo→dir com captura a cada jogada
for mv in "120 200 120 80" "200 120 80 120" "120 80 120 200" "80 120 200 120"; do
    $CTL -p /dev/ttyUSB1 swipe $mv
    sleep 0.7
    $CTL -p /dev/ttyUSB1 screencap frame.png
done
✓

Truques da casa: tap segura ~150 ms — dê um sleep curto antes do screencap para a animação assentar; o GIF do Snake nesta wiki é literalmente 8 desses frames com Pillow (quantize + save_all).

Apps por USB #

▸bash
$CTL -p /dev/ttyUSB1 apps list
sistema  App Store        v2.6.0      api 22  celeros.appstore
sistema  Settings         v1.8.0      api 22  celeros.settings
local    Snake            v1.3.0      api 22  celeros.snake
…

# instala pasta local (lint incluso) e já abre
$CTL -p /dev/ttyUSB1 apps install minha-pasta --run

# no cartão de memória, quando a placa tem
$CTL -p /dev/ttyUSB1 apps install minha-pasta --sd

# traz um app instalado de volta pro PC
$CTL -p /dev/ttyUSB1 apps pull celeros.snake ./snake

Logs e debugger #

▸bash
# stream de logs (Ctrl-C sai; --dump copia o buffer e sai)
$CTL -p /dev/ttyUSB1 logcat
$CTL -p /dev/ttyUSB1 logcat --dump | grep -i sd

# crash? o coredump vira ELF p/ addr2line/gdb
$CTL -p /dev/ttyUSB1 coredump

# debugger do JS: breakpoints em linha, eval no escopo do app
$CTL -p /dev/ttyUSB1 debug "App Store"

Firmware pela serial #

▸bash
# grava no slot inativo pela própria conexão e reinicia
$CTL -p /dev/ttyACM2 --win 2 ota push build-watch/CelerOS.bin
ota CelerOS.bin -> app0: [########################] 1612208/1612208 bytes
OTA ok: 1612208 bytes em 'app0'
reiniciando para o novo firmware…
!

Uma sessão celerctl por porta por vez (serial é exclusiva). Se um comando "travar", confira se não há outro logcat/dev segurando a porta — o erro clássico é nao responde ao protocolo HostLink.
