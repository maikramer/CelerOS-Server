OTA & firmware

Cada placa tem seu canal no hub (/updates/<canal>) com um update.json e o binário. O aparelho compara versões, grava no slot inativo e só troca de boot depois de validar — nunca se bricks em campo.

GET /updates/* publish: POST /admin/updates/<canal> anti-rollback 409

Slots A/B — como o aparelho atualiza #

update.json, campo a campo #

O manifest real do canal esp32 hoje:

▸content/updates/esp32/update.json
{
  "version": "1.1.0",
  "api_version": 22,
  "major_update": false,
  "minor_update": false,
  "security_update": false,
  "changelog": "CelerOS Hub no ar (os.celer.tec.br). Canal de updates migrado…",
  "guide": "Abra Settings > Atualizacao e toque em INSTALL.",
  "firmware_url": "firmware.bin",
  "firmware_sha256": "…"
}
CampoRegra no hub
versionsemver; o device instala só se > que a gravada nele
api_versionint 1..999, default = nível vigente do hub (FIRMWARE_API_LEVEL). O aparelho recusa manifest abaixo do próprio nível — o hub valida no publish
major/minor/security_updateflags de UI (badges na tela de OTA)
changelog guidetexto; changelog aparece na tela de atualização
variantSKU opcional (ex.: smartdisplay-y8 para a SmartDisplay com relés). Device com variante recusa manifest sem a própria — publique imagem de variante em canal próprio
firmware_urlrelativa ao diretório do manifest (normalmente firmware.bin); sem binário, o publish remove o campo e o arquivo do canal (manifest-only)
firmware_sha256computado no publish a partir do binário enviado

Publicar firmware #

▸bash
# canal da placa: esp32 | smartdisplay_4848S040 | waveshare_amoled206 | spotpear_zzpet | devkit
python3 tools/publish_firmware.py esp32 build-cyd/CelerOS.bin \
  --version 1.8.0 --changelog "- SD no CYD; correcoes da loja" \
  --hub https://os.celer.tec.br --token $CELER_HUB_TOKEN_CI

# variante SmartDisplay Y (relés) — canal próprio + --variant
python3 tools/publish_firmware.py smartdisplay_4848S040 build-y/CelerOS.bin \
  --version 1.8.0 --variant smartdisplay-y8 --token $CELER_HUB_TOKEN_CI
  • Anti-rollback: publicar versão menor que a atual do canal → 409. Exceção consciente: --force.
  • Manifest-only: sem binário, o canal anuncia a versão sem firmware (útil para notas/migração de hub) e o firmware.bin antigo é removido.
  • Atomicidade: o binário grava como firmware.bin.tmp e vira firmware.bin por rename — cliente nunca lê meio arquivo.

No CI (GitHub Actions)

▸.github/workflows/ota.yml
- name: Publicar OTA
  run: |
    python3 CelerOS-Server/tools/publish_firmware.py esp32 \
      build-cyd/CelerOS.bin --version ${{ steps.ver.outputs.v }} \
      --changelog "${{ github.event.head_commit.message }}" \
      --hub https://os.celer.tec.br --token ${{ secrets.CELER_HUB_TOKEN }}

O token do CI precisa só do escopo updates.

OTA por USB, sem esptool #

Para gravar direto do PC pela conexão do celerctl (o caminho do relógio, sem botões expostos):

▸bash
python3 tools/celerctl.py -p /dev/ttyACM2 --win 2 ota push build-watch/CelerOS.bin
# ota CelerOS.bin -> app0: [####…] 1612208/1612208 bytes
# reiniciando para o novo firmware…
!

Gravando firmware mais novo que o canal? Atualize o canal em seguida — o aparelho compara com o manifest do hub e "sistema atualizado" para tudo que não for versão maior.
