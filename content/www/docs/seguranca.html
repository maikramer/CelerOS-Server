Segurança

O modelo é curto de propósito: leitura pública, escrita autenticada com escopo, tudo auditado. A loja, o OTA e a ajuda não autenticam porque o dispositivo não tem conta — a proteção do lado da escrita é que decide o jogo.

leitura pública por design Bearer + escopo auditoria append-only

Tokens & escopos #

Dois sabores, ambos em Docker secrets (nunca em environment/commit):

  • Root — secret celeros_hub_admin_token, escopo * (retrocompatível com a era de um token único).
  • Nomeados — secret celeros_hub_tokens, um JSON [{"name","token","scopes"}] gerado pelo tools/make_tokens.py. Cada token tem escopo explícito e o nome aparece na auditoria.
EscopoPermitePara quem
*tudovocê (root)
appspublicar/remover apps da lojacolaboradores
updatespublicar/remover canais OTACI / publicador de firmware
▸bash — ciclo de vida de um token
python3 tools/make_tokens.py > tokens.json      # gere; edite nomes/escopos
docker secret create celeros_hub_tokens tokens.json && shred -u tokens.json

# conferir um token (o CI pode validar antes de publicar)
curl -s -H "Authorization: Bearer $T" https://os.celer.tec.br/admin/whoami
# → {"name":"ci","scopes":["updates"]}

Rotação sem restart: o hub relê o arquivo de tokens a cada request — recriar o secret + denv update basta (secrets são imutáveis no Swarm, por isso o rm+create). Comparação de token é secrets.compare_digest (constante-time).

Rate limit de autenticação #

  • 10 falhas de auth em 10 min do mesmo IP → bloqueio de 15 min (429 + Retry-After).
  • O IP vem do X-Forwarded-For do Traefik — confiança válida porque o container não publica porta no host: só o reverse proxy o alcança.
  • Sem nenhum secret configurado, o /admin responde 503 — servidor sem credencial é servidor com admin desligado, não aberto.

Auditoria #

Append-only em /mnt/nfs/celeros-hub/audit/audit.log — fora do rsync de conteúdo de propósito (deploy não mexe no histórico). JSON-lines:

▸audit.log
{"ts":"2026-10-05T21:26:11Z","ip":"203.0.113.7","agent":"ci","action":"ota:publicar","target":"esp32","ok":true}
{"ts":"2026-10-05T21:27:02Z","ip":"203.0.113.9","action":"auth/falha","ok":false,"err":"token invalido"}

Ações registradas: auth/falha, auth/escopo:<s>, app:publicar, app:remover, ota:publicar, ota:remover. A auditoria nunca derruba a request — falha nela é falha silenciosa do log, não do serviço.

Uploads validados #

Cada camada do publish de app existe por um motivo:

CamadaProteção
Tetos de tamanhobody ≤ 49 MB, zip lido ≤ 48 MB, soma descomprimida ≤ 64 MB (zip-bomb)
Nomes de arquivoregex ^[A-Za-z0-9._-]{1,64}$, colisão de basename → 400 — sem path traversal
Whitelist de extrassó .js .png .wav .json .bin; ≤ 16 arquivos / 128 KB cada / 256 KB total
Íconemagic bytes PNG + ≤ 16 KB
MetadadospackageName/semver/canal validados por regex; requires ⊆ psram
Escritastaging <pkg>.tmp + swap rmtree/rename — nunca meio pacote no ar
Possequem publicou primeiro é o dono do packageName; republicação exige versão maior

No OTA: anti-rollback (versão menor → 409, força exige force=1), binário gravado com tmp+rename e firmware_sha256 registrado no manifest.

Superfície & transporte #

  • TLS termina no Traefik (entrypoint websecure, cert da zona celer.tec.br); o container só fala HTTP na rede interna.
  • Swagger desligado em produção (HUB_DOCS=1 liga em dev) — /api/docs nem existe por padrão.
  • Headers em todas as respostas: nosniff, X-Frame-Options: DENY, no-referrer.
  • 404 sempre JSON — sem stack trace, sem template de erro.
  • Container enxuto: python alpine, uma porta interna, zero shell de sistema no app.

Consciente e anotado (evoluções) #

!

Duas frentes estão documentadas como próximas passos, não como defesa vigente: verificação do sha256 no dispositivo (o campo já vai no manifest; o firmware atual ainda não confere) e CA pinning no esp_https_ota (hoje setInsecure — TLS termina protegendo o caminho servidor↔Traefik↔internet, com o aparelho confiendo na rede). Nada disso abre escrita no hub; é integridade de ponta a ponta no caminho do firmware.

Vazou um token? #

Tire o token do ar

Edite o tokens.json local removendo a entrada (ou regenere todos — make_tokens.py de novo).

Recrie o secret

docker secret rm celeros_hub_tokens && docker secret create … + denv update celeros-hub -t <tag>. O hub relê a cada request: revogação é imediata no próximo deploy do secret.

Confira a auditoria

grep '"agent":"<nome>"' audit.log — todas as ações do token estão lá com IP e timestamp.
